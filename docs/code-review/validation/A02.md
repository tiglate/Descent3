## Batch 3: network string helpers and portal indexes (2026-11-10)

### Network strings

`MultiGetString` copied up to the 255 bytes announced by the packet's length
byte into the caller's buffer, and relied on the sender for a terminator. Six
call sites write into `msafe_struct::name[32]` (`multisafe_server.cpp`) and one
into `DMFC_team_names[team][16]` (`dmfcpackets.cpp`). A peer sending a longer
string overflowed those fields, and no destination was guaranteed to be
terminated.

`MultiGetString` now takes the destination size, and an array-reference
template supplies it at every call site. The compiler accepted all 21 existing
calls unchanged, so each one passes a real array. The copy is clamped and
always terminated, and the read position still advances by the full encoded
length, so following fields stay aligned.

`MultiAddString` truncates strings over 254 characters instead of writing a
wrapped length byte (the old check was a debug-only `assert`). The packet
format is unchanged. The helpers are inline in `multi_external.h`, so loadable
modules get the fix when rebuilt, and the module ABI is unchanged.

`multi_string_tests` (Linux) covers four cases:

- round trip and field alignment
- a 200-byte unterminated string into a 32-byte field (truncated, terminated,
  and the next field still read correctly)
- empty and exact-fit strings
- clamping of over-long outgoing strings, which runs in Release because Debug
  keeps the `assert`

Not covered: the `MultiGet*` readers in general still trust that a packet
holds the fields they read. Bounding reads to the received packet length
needs the packet size plumbed through every handler, and is a separate
multiplayer hardening task.

### BOA portal indexes

`BOA_DetermineStartRoomPortal` can return -1. These uses now treat that as "no
connecting portal", matching the neighboring checks:

- `hlsoundlib.cpp`: two distance branches add no portal distance or cost.
- `aipath.cpp`: the external-room branch skips the neighbor.

### Verification

- Debug and Release builds pass; CTest passes 234 of 234 in both
  configurations (one opt-in real-GL test skipped).
- The gate reports 35 findings, zero new.
- A rescan of the touched files shows only the previously triaged `aipath.cpp:86`
  ownership false positive.

## Batch 4a: special-packet size (2026-11-10)

`MultiDoSpecialPacket` copied a network-supplied `size` into a
`MAX_GAME_DATA_SIZE` stack buffer, guarded only by a debug assert. Clients
handle `MP_SPECIAL_PACKET` from the server, and the server handles the same
packet type from any connected client (`MultiClientSendSpecialPacket`), so a
negative or oversized `size` overflowed the stack on either side.

The handler now receives the sub-packet length validated by
`MultiProcessBigData`. It rejects a size that is negative, larger than the
buffer, or larger than the rest of the sub-packet, and zero-fills the buffer
handed to the game module. Both senders refuse a payload that does not fit.
Verified by source review, Debug and Release builds, and CTest 234 of 234 in
both configurations. No multiplayer session was run.
