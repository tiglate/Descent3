# M05 / B02 — console initialization and file-size failure handling

**M05: Done. B02: Review**, pending Windows compilation/runtime validation of the
updated backend. Linux Debug engine integration, regressions, sanitizer checks,
and focused Release console/registry tests passed.

The raw console allocates and initializes both buffers in temporary owners before
publishing either. Failed first/second allocation releases temporary storage;
failed reinitialization leaves the previous console and pending command intact.
Successful reinitialization releases the old buffers. Destroy is repeatable and
resets input state; a closed/failed console does not poll keys. Null or nonpositive
input-buffer capacity is rejected before accessing or consuming a command.
The console dimensions and normal command-editing behavior are unchanged.

POSIX file-length queries now check the descriptor and fstat result before using
the size, reject negative/out-of-int-range sizes, and narrow only after validation.
The Windows counterpart uses `_filelengthi64` before applying the same int limit,
with null/negative-descriptor checks. These preserve the existing API and file
formats rather than widening serialized fields. The API reports -1 on failure.
Disk CFILE opening closes the stream and returns null if the size query fails;
it cannot publish -1 as the unsigned size 0xffffffff. HOG entry handling is unchanged.

Console tests supply keyboard events to the production driver, avoiding input
devices. They exercise command entry, backspace editing, single consumption,
create/recreate/destroy, failed reinitialization, retries, invalid output storage,
and no key polling after failure/destroy. Linux-only malloc/free wrappers inject
failures and account for live console buffers without changing production APIs.
Test targets disable malloc builtin optimization so optimized builds cannot
bypass the fault injection by replacing allocation calls.

File tests cover null FILE pointers, empty/normal files without changing position,
POSIX fstat failure, INT_MAX, INT_MAX+1 and positive-wraparound sizes above 4 GiB.
Temporary sparse files supply large logical lengths without writing gigabytes of
data. The CFILE tests verify that errors are rejected by the actual caller while
supported file contents and sizes remain intact. Invalid-descriptor and sparse
boundary cases are POSIX-specific; Windows checks remain a separate gate.

The implementation follows the failure-result contract of
[fstat](https://man7.org/linux/man-pages/man2/stat.2.html) and the wide-size query
documented for
[_filelengthi64](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/filelength-filelengthi64?view=msvc-170).
Other clang-tidy findings are still tracked separately, including the open-file
allocation/`Error()` control-flow candidate in T03. No blanket fix or analyzer
suppression was added. Real keyboard/gameplay and Windows smoke sessions were not
performed in this batch; fixtures do not modify user preferences or game assets.
