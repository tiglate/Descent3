# M02 / M03 — WAV file and sample ownership

**M02: Done. M03: Review**, with an in-game audio smoke check still pending.
Linux Debug engine integration, generated WAV regressions, and memory sanitizer
checks are complete. Windows execution was not performed in this workspace.

`SoundLoadWaveFile` now owns its `CFILE` handle through a scoped `cfclose` deleter.
An error after the normal parsing loop cannot close freed storage a second time.
Both sample formats also have scoped owners. Samples are transferred into the
sound slot only after parsing and quality conversion succeed; failure preserves
previously loaded samples, and successful replacement frees the old allocation.

For multiple `fmt`/`data` waveforms, the last complete waveform still wins.
Earlier buffers are released before loading the next waveform, including when
bit depth changes. This preserves the legacy selection policy rather than
concatenating sounds or rejecting a previously accepted multi-waveform sequence.
The plan's M03 action was refined to record that implementation choice.

The loader now checks RIFF and chunk boundaries before reading or allocating,
checks numeric/sample reads, rejects incomplete 16-bit samples, bounds allocation
sizes for the existing int-sized APIs, and checks allocation results. It skips
RIFF word padding and tolerates a missing pad on a final odd-length chunk for
legacy compatibility. This follows the chunk-size/padding distinction in
[Microsoft's RIFF documentation](https://learn.microsoft.com/en-us/windows/win32/xaudio2/resource-interchange-file-format--riff-).
The supported mono PCM format, 22050-Hz rate, sample alignment, and volume and
quality-conversion formulas remain unchanged.

Fixtures cover missing files/data/format, metadata-only loads, valid 8/16-bit
samples and quality conversion, exact padded sample values, repeated waveforms,
mixed bit depths, successful/failed replacement, malformed RIFF lengths, truncated
headers, out-of-bounds chunk sizes, short format chunks, incomplete 16-bit samples,
and odd-chunk padding. Tests compile the production loader and use real CFILE
operations; only the two gameplay paging counters are supplied by the harness.

The original-loader comparisons compiled the pre-change source against the same
sanitized test object and libraries. Local evidence is retained under ignored
`build/code-review/`: `wave-validation.json`, `baseline-missing-data.log`,
`baseline-repeated-waveform.log`, `fixed-stress.log`, and `wave-final-ctest.log`.
LeakSanitizer needed authorized execution outside the sandbox for process
inspection, including CMake's test-discovery step. The sanitizer build instruments
the loader and its repository dependencies; prebuilt SDL/GTest are not instrumented.

Normal verification:

```sh
rtk proxy cmake -S . -B build -DBUILD_TESTING=ON
rtk proxy cmake --build build --config Debug --target wave_loader_tests Descent3 --parallel 4
rtk proxy ctest --test-dir build -C Debug --output-on-failure
```

Sanitizer verification reuses the existing dependency installation in a separate
build directory:
