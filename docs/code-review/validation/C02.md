# C02: HTTP timeout options

`D3::HttpClient` used to hard-code a 5-second connect timeout and inherit
cpp-httplib's 300-s read and 5-s write timeouts. It now takes a
`D3::HttpTimeouts` options object; the one-argument constructor keeps the old
values.

- **Units:** whole seconds. *connect* bounds TCP connection establishment.
  *read* and *write* bound each socket operation (inactivity), not the total
  transfer time.
- **Ranges:** connect 1–60 s, read/write 1–600 s. Invalid values given to the
  constructor are replaced with the defaults, so no request can wait without
  bound.
- **User options:** `-httpconnecttimeout` (default 5) and `-httpreadtimeout`
  (default 300) apply to mission downloads, beside the existing `-httpproxy`.
  Malformed or out-of-range values are ignored with a warning, and the
  effective values are logged. Documented in USAGE.md.
- The Descent3 Online game-list fetch (`dip_gametrack.cpp`) runs in a loadable
  netcon module without access to game arguments, so it keeps the defaults.
- **Defect fixed in passing:** `FetchApi` read `result->status` without checking
  the result. A refused or timed-out request produced a null `httplib::Result`
  and a null dereference. It now logs the error and returns.

## Evidence (Linux, 2026-11-10)

`httpclient_timeout_tests`: 9 GoogleTest cases against a loopback cpp-httplib
server, all passing:

- defaults equal the previous behavior
- option parsing (10 malformed/out-of-range inputs plus null)
- range validation
- a fast request succeeds
- a 1-s read timeout fails a 2-s delayed response with `Error::Read` after about 1 s
- a 5-s read timeout receives it
- an invalid timeout falls back to the default and succeeds
- a progress callback cancels a streamed download with `Error::Canceled`
- a refused port reports `Error::Connection` with no response object (the
  `FetchApi` crash condition)

In the Debug game, `-httpconnecttimeout 10 -httpreadtimeout 0` logged the
warning for the invalid read value and "connect 10s, read 300s, write 5s".
