# M04 / B01 — registry allocation safety and INF operand bounds

**M04: Done. B01: Done.** Linux Debug engine integration, targeted regressions,
and address/undefined-behavior/leak sanitizer runs passed. Windows execution and
interactive gameplay were not performed for this batch.

Registry record creation now allocates and copies the value before changing an
existing record or linking a new one. Allocation failure returns false without
losing the previous value/type or inserting a partial record. Input may alias the
old value because copying finishes before the old allocation is freed. The
temporary `olddata` allocation and copy-only lookup were removed. Unsupported
record types, null record input and names exceeding the fixed name field are
rejected before allocation. Registry structures and the file format are unchanged.

Destroying the old registry now clears the selected key as well as the root,
preventing stale-key access after an empty import. Invalid or failed key creation
also clears selection so subsequent writes cannot silently modify the prior key.
Allocation guarantees apply to the individual creation/replacement operations;
this is not a redesign of the whole-file import parser.

The INF parser now resolves a complete symbol name independently of output
capacity, then checks the expanded value including its terminator before copying.
An oversized or missing symbol returns `INFFILE_ERROR` with an empty operand.
Literal operands keep their existing truncation behavior. Invalid output storage
returns an error without consuming the line. Delimiter-only input, pre-open and
post-close parser calls are safe. Symbol construction uses scoped allocations so
an exception during value allocation cannot leak its unlinked list node.

The registry tests inject failure at both allocations of a new string/DWORD
record, at the replacement allocation, and at key allocation. They cover both
empty and populated lists, retries, type changes, aliases, case-insensitive
replacement, maximum accepted names, invalid inputs, empty import and valid
string/DWORD export-import round trips. Failure injection uses the Linux linker's
malloc wrapper only in the test executable; no allocator override was added to
the production API. Other platforms can run the non-injection cases.

INF cases cover oversized/exact-fit values, full symbol names with small outputs,
missing/empty symbols, one-byte buffers, null/zero/negative capacities, delimiter
input, multiple commands/comments, closed-parser behavior and symbol cleanup on
reopen. The fixtures use temporary files and real CFILE operations. They do not
write user preferences or commercial assets.

Remaining clang-tidy findings include generic unbounded-copy API warnings,
legacy traversal dead stores, enum-size advice and registry import-parser
diagnostics. Some reported copies already have checked source/destination sizes;
this batch does not claim to clear all registry/parser warnings. No analyzer
suppression or blanket automatic fix was added. The remaining cfopen/renderer
analyzer candidates stay in T03.
