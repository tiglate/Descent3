# C03: SDL sound-buffer option

`-sdlSndSize` was parsed into `sampleCount` and then discarded, so it had no
effect. It is now wired to SDL3's `SDL_HINT_AUDIO_DEVICE_SAMPLE_FRAMES`, set
before the device is opened. The option was kept, not retired, because
SDL 3.2 provides a supported way to honor it.

- **Units:** device sample frames (one frame = one sample per channel at the
  device rate, e.g. 48 kHz on PipeWire), not frames of the 22050-Hz content.
- **Range:** integer 64–8192. Missing, malformed (`512ms`, `+512`, `1e3`), and
  out-of-range values are ignored with a warning, and SDL picks the size.
- **Default:** unchanged. Without the option no hint is set.
- **Precedence:** an `SDL_AUDIO_DEVICE_SAMPLE_FRAMES` environment variable
  overrides the option (SDL ignores normal-priority hints when the variable is set).
- SDL treats the value as a request; the obtained size is now logged after the
  device opens. The 22050-Hz content interpretation is unchanged.

## Evidence (Linux, 2026-11-10)

- `sound_buffer_option_tests`: 3 GoogleTest cases (valid, boundary, malformed,
  null, overflow, out-of-range) pass in the Debug build.
- Stand-alone SDL 3 probe against PipeWire: default → 1024 frames; hint 256 →
  256; hint 2048 → 2048.
- Debug game binary, 15-second windowed launch:
  - `-sdlSndSize 512` logs "requested device buffer of 512 sample frames", then
    "device 48000 Hz, 2 channels, buffer 512 sample frames", and loads
    `startup.wav`.
  - `-sdlSndSize bogus` logs the warning and opens the default 1024-frame buffer.
