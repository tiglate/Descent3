# C01: Network timing policy

`NETTIMEOUT` used to drive both the connection handshake wait and established-peer
expiry. Resend intervals were fixed at compile time. `lib/net_timing.h` now
defines `nw_timing_policy`, and `networking.cpp` reads it through
`nw_SetTimingPolicy`/`nw_GetTimingPolicy`.

| Option | Field | Default | Range |
| --- | --- | --- | --- |
| `-netconnecttimeout` | connect handshake (client wait, half-open/limbo sockets) | 300 s | 1–600 |
| `-netidletimeout` | established peer silence | 300 s | 30–3600 (≥ 3 × 10-s heartbeat) |
| `-netretrytime` | base resend interval | 0.75 s | 0.05–5 |
| `-netminretrytime` | ping-derived resend floor | 0.2 s | 0.05–retry time |

- Precedence: a valid command-line value replaces the default; there is no
  registry setting.
- A malformed value (sign, exponent, `nan`/`inf`, hex, trailing text) is ignored
  with a warning.
- An inconsistent or out-of-range combination keeps all four defaults, with one
  warning.
- The effective policy is logged at startup. Defaults are compile-time asserted
  to equal the legacy macros.
- Packet layouts, sizes, `NETHEARTBEATTIME` and the 2-s connect-request resend are
  unchanged. The legacy macros stay in `networking.h` for netcon module
  compatibility.

## Evidence (Linux, 2026-11-10)

- `net_timing_tests`: 6 GoogleTest cases cover:
  - the legacy defaults
  - valid overrides
  - connect/idle independence
  - ten malformed inputs and a missing argument
  - nine out-of-range or inconsistent combinations
  - NaN/inf and exact boundaries
- Debug engine build passes.
- Debug game: `-netconnecttimeout 3 -netidletimeout 60` logged
  "connect 3.00s, idle 60.00s, retry 0.75s (min 0.20s)". The options
  `-netretrytime 0.3 -netminretrytime 0.5 -netconnecttimeout abc` logged the
  malformed-value warning and the inconsistency warning, then kept the defaults.
