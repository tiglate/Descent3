# M01 — asynchronous DNS ownership and synchronization

Status: **Review**. Linux implementation and automated validation are complete;
Windows compilation/runtime checks and a multiplayer smoke session remain open.

The polling function and module API slot 86 retain their signatures and command
IDs. LOOKUP now owns a copy of the hostname. A single owner joins its SDL worker
before replacement, cancellation, result consumption or destruction. Atomic
release/acquire publication replaces unsynchronized flags. Workers never free
request storage. Networking shutdown joins DNS before Winsock cleanup, including
when socket initialization did not complete.

The resolver uses IPv4 `getaddrinfo` with scoped `freeaddrinfo` cleanup and returns
the same network-byte-order address representation. Windows now requests Winsock
2.2 and links ws2_32 explicitly. The former platform-specific workers and unused
pthread loader were removed. No other D02 cleanup is claimed complete.

Cancellation/replacement still waits for an in-flight OS resolver call to return;
it is not a DNS deadline or an interruption mechanism. The API remains a single
lookup service called serially by the game thread. Invalid/null hostname or
thread-creation failure returns -1; a pending READ returns 0; success returns 1
once. CANCEL retains its legacy -2 return value. READ with null output returns -1
without consuming the request.

Tests exercise hostname mutation after LOOKUP, pending READ, replacement before
consumption, cancellation, destructor joining, failed resolution/retry, injected
thread-creation failure/retry, invalid inputs, resolver exceptions and numeric
loopback resolution. Fake blocking resolvers make ownership paths deterministic;
the real numeric-address case requires no external DNS or connection.

The sandboxed TSan run passed all test iterations but failed during exit-time
LeakSanitizer process inspection. Repeating the same command with the authorized
sandbox escalation exited successfully with no sanitizer reports. Sanitizers
instrument the DNS implementation and tests; prebuilt SDL/GTest and the rest of
the engine were not instrumented by the focused harness.

To repeat the normal build and tests:

```sh
rtk proxy cmake -S . -B build -DBUILD_TESTING=ON
rtk proxy cmake --build build --config Debug --target async_dns_tests Descent3 --parallel 4
rtk proxy ctest --test-dir build -C Debug --output-on-failure
```

To configure a focused sanitizer build using the existing dependency installation:

```sh
rtk proxy cmake -S networking/tests/sanitizers -B build/code-review/m01-asan -G Ninja \
  -DCMAKE_PREFIX_PATH="$PWD/build/vcpkg_installed/x64-linux" \
  -DCMAKE_CXX_COMPILER=clang++ -DCMAKE_BUILD_TYPE=Debug \
  '-DCMAKE_CXX_FLAGS=-fsanitize=address,undefined -fno-omit-frame-pointer' \
  '-DCMAKE_EXE_LINKER_FLAGS=-fsanitize=address,undefined'
rtk proxy cmake --build build/code-review/m01-asan --parallel 2
rtk proxy env ASAN_OPTIONS=detect_leaks=1:halt_on_error=1 UBSAN_OPTIONS=halt_on_error=1 \
  build/code-review/m01-asan/async_dns_tests --gtest_repeat=100 --gtest_brief=1
```

For TSan, use a different build directory, replace both sanitizer flags with
`-fsanitize=thread`, and run with `TSAN_OPTIONS=halt_on_error=1`. The initial
sanitizer executions used an equivalent generated minimal harness under
`build/code-review/dns-harness`; the maintained harness above uses the same source
files, imported dependency targets and compiler flags. The initial binaries are
`build/code-review/dns-asan/async_dns_tests` and
`build/code-review/dns-tsan/async_dns_tests`.

Thread creation/join handling follows the official
[SDL_CreateThread](https://wiki.libsdl.org/SDL3/SDL_CreateThread) and
[SDL_WaitThread](https://wiki.libsdl.org/SDL3/SDL_WaitThread) contracts. The resolver
uses the reentrant interface described in the
[getaddrinfo manual](https://man7.org/linux/man-pages/man3/getaddrinfo.3.html).
